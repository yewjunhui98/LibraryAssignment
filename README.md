# Library API

REST API for a small library. Staff can register borrowers, register book copies, list every copy, and borrow or return a copy on behalf of a borrower.

The interactive API reference is Swagger UI: [http://localhost:8080/swagger-ui.html](http://localhost:8080/swagger-ui.html). The OpenAPI document is at [http://localhost:8080/v3/api-docs](http://localhost:8080/v3/api-docs). Opening [http://localhost:8080/](http://localhost:8080/) redirects to Swagger UI.

## Stack

- Java 17 and Spring Boot 3
- Maven
- Microsoft SQL Server, via the Azure SQL Edge container (ARM64)
- Flyway migrations
- springdoc OpenAPI (Swagger UI)

The database is relational on purpose. A borrower email is unique, an ISBN has one title and author, and a book copy has at most one active loan. SQL Server enforces those rules with constraints, including a filtered unique index on the active loan, and the API process stays stateless.

SQL Server Express was the intended edition. Its official container is linux/amd64 only, and on this Apple Silicon Podman machine that image exits immediately with a segmentation fault under qemu (exit 139). Azure SQL Edge is Microsoft's ARM64 SQL Server engine. It uses the same wire protocol, the `sa` login, and the `/var/opt/mssql` data directory, so the API and the Flyway scripts are unchanged.

## Run with Podman

The SQL Server data directory is `sqlserver-data/` in this folder. It is bind-mounted to `/var/opt/mssql` inside the database container.

The Podman machine needs about 6 GB of RAM so the database and the API can run together. The database container is ARM64, so it does not need emulation.

```bash
mkdir -p sqlserver-data
chmod 777 sqlserver-data
podman machine stop
podman machine set --memory 4096
podman machine start
podman compose up --build
```

If Compose fails with `docker-credential-desktop`, point it at an empty Docker config:

```bash
mkdir -p /tmp/library-docker-config
printf '%s\n' '{}' > /tmp/library-docker-config/config.json
DOCKER_CONFIG=/tmp/library-docker-config podman compose up --build
```

- API: `http://localhost:8080`
- SQL Server (Azure SQL Edge): `localhost:1433`, database `library`, user `sa`
- Default SA password: `Library_Assign1!` (override with `MSSQL_SA_PASSWORD` or a `.env` file copied from `.env.example`)

Configuration is environment variables, listed in `compose.yaml` and `src/main/resources/application.yml`. Logs go to stdout.

## API

| Action | Method and path | Success |
| --- | --- | --- |
| Register a borrower | `POST /api/borrowers` | 201 |
| Register a book copy | `POST /api/books` | 201 |
| List every book copy | `GET /api/books` | 200 |
| Borrow a copy | `POST /api/books/{bookId}/borrow` | 200 |
| Return a copy | `POST /api/books/{bookId}/return` | 200 |

```bash
curl -s -X POST http://localhost:8080/api/borrowers \
  -H 'Content-Type: application/json' \
  -d '{"name":"Ada Lovelace","email":"ada@example.com"}'

curl -s -X POST http://localhost:8080/api/books \
  -H 'Content-Type: application/json' \
  -d '{"isbn":"978-0-13-468599-1","title":"Effective Java","author":"Joshua Bloch"}'

curl -s http://localhost:8080/api/books

curl -s -X POST http://localhost:8080/api/books/1/borrow \
  -H 'Content-Type: application/json' \
  -d '{"borrowerId":1}'

curl -s -X POST http://localhost:8080/api/books/1/return \
  -H 'Content-Type: application/json' \
  -d '{"borrowerId":1}'
```

Validation errors return 400 with `fieldErrors`. Unknown borrowers or books return 404. Conflicts return 409: duplicate email, an ISBN reused with a different title or author, borrowing a copy that is already out, or returning a copy for someone who does not hold it.

`GET /api/books` includes `status` (`AVAILABLE` or `BORROWED`) and `borrowedBy` when the copy is out.

## Assumptions

- Callers are not authenticated. "On behalf of a borrower" means the request body contains that borrower's id.
- Borrower and book ids are generated by the database. Clients do not supply them.
- Email addresses are unique. They are stored in lower case, so `Ada@Example.com` and `ada@example.com` are the same borrower.
- Names, titles, and authors are trimmed and internal whitespace is collapsed. Title and author comparison is case-sensitive.
- ISBN-10 and ISBN-13 are accepted when the checksum is valid. ISBN-10 is stored as the equivalent ISBN-13 using the `978` prefix. Hyphens and spaces are ignored.
- Two copies with the same ISBN are different books and receive different ids. They must share the same title and author. That pair is stored once in `isbn_records` and enforced by the primary key.
- A borrower may hold many copies. A single book id may have only one active loan. Returning a copy records `returnedAt` and the copy can be borrowed again. Loan history is kept.
- Only the borrower who currently holds a copy can return it.
- The list endpoint returns every copy. There is no paging, update, or delete.
- There is no due date, fine, or limit on how many copies one borrower may hold.

## Tests

Tests use an in-memory H2 database so they do not need SQL Server.

```bash
podman run --rm -v "$PWD":/app -w /app docker.io/library/maven:3.9.9-eclipse-temurin-17 mvn -B test
```

GitHub Actions runs the same Maven test goal on every push (`.github/workflows/ci.yml`).

## Layout

- `src/main/java/com/library` — borrowers, books, loans
- `src/main/resources/db/migration` — SQL Server schema
- `Dockerfile` — API image
- `compose.yaml` — API and Azure SQL Edge
- `sqlserver-data/` — database files on the host
